## 1. 변경 개요

| 항목 | 기존 | 변경 |
|---|---|---|
| 성향 데이터 | `traits: string[]` (자유텍스트 5개 혼재) | **기질 5칼럼 + 부모 5칼럼**으로 분리 |
| 기질 칼럼 | (구분 없음) | 5칼럼 명시 (유지: 5개) |

## 2. 칼럼 정의

### 2-1. 기질 5칼럼 `temperament`

| 칼럼 | 의미 | 이론 근거 |
|---|---|---|
| `활동성` | 신체·에너지·주도성 | Rothbart 외향/활발성(Surgency) + Thomas&Chess 활동성 |
| `사회성` | 또래관계·리더십·협력 | Thomas&Chess 접근/회피(Approach) |
| `정서성` | 기분·자신감·감정표현 | Rothbart 부정정서(Negative Affectivity) |
| `적응성` | 새 상황 접근 속도·적응 | Thomas&Chess 적응성(Adaptability) |
| `자기조절` | 집중·주의지속·차례 기다리기 | Rothbart 의도적 통제(Effortful Control) |

**근거 출처**
- Rothbart CBQ(만 3~7세, 3요인·15차원, 교차문화 재현): https://research.bowdoin.edu/rothbart-temperament-questionnaires/instrument-descriptions/the-childrens-behavior-questionnaire/ · https://pubmed.ncbi.nlm.nih.gov/11699677/
- Thomas & Chess 뉴욕 종단연구(9차원·3유형): https://socialsci.libretexts.org/Bookshelves/Human_Development/Lifespan_Development_(OpenStax)/04:_Social_and_Emotional_Development_in_Infants_and_Toddlers_(Birth_to_Age_3)/4.02:_Temperament_and_Personality_in_Infants_and_Toddlers

> 칼럼명은 **현재 시드의 traits 내용**(신체·또래·기분·적응·집중 관련 서술)에 맞춰 5개 차원으로 재구성했습니다.

### 2-2. 부모 5칼럼 `parent`

| 칼럼 | 의미 |
|---|---|
| `가정에서의모습` | 가정에서 관찰되는 행동·기질 |
| `강점재능` | 부모가 보는 강점·재능 |
| `우려요청` | 우려 사항·교사에게 요청 |
| `또래형제관계` | 형제·또래 관계 정보 |
| `양육방식` | 양육 태도·가정의 약속 |

> ⚠️ **현재 시드에 부모 제공 정보가 없어 값은 모두 빈 문자열("")** 입니다. 기획문서/부모상담 입력 시 채웁니다. (칼럼 **명칭/스키마**만 우선 확정)

### 2-3. 기질 예민도 `sensitivity` (상/중/하)

| 값 | 의미 | 비유 |
|---|---|---|
| `상` | 고민감 — 환경 자극에 민감, 긍정 환경에서 특히 크게 성장 | 난초(orchid) |
| `중` | 중간 민감 | 튤립(tulip) |
| `하` | 저민감 — 안정적, 환경 변화에 덜 흔들림 | 민들레(dandelion) |

**근거 출처**: Pluess 외(2018) Highly Sensitive Child Scale — 저/중/고 3그룹: https://www.researchgate.net/publication/319974199_Environmental_Sensitivity_in_Children_Development_of_the_Highly_Sensitive_Child_Scale_and_Identification_of_Sensitivity_Groups · Vantage Sensitivity(PMC5959990): https://www.ncbi.nlm.nih.gov/pmc/articles/PMC5959990/

**현재 기본값 분포** (traits의 정서·위축·완벽주의 단서로 추정)

| 예민도 | 원아 |
|---|---|
| 상 | 지연 · 도윤 · 소민 · 진우 |
| 중 | 민준 · 윤호 · 예진 · 다은 · 서진 · 서우 · 건호 |
| 하 | 시우 · 하늘 · 태오 · 호준 |

> 기본값은 **추정치**입니다. 교사·부모 확인 후 보정 필요(후순위 기능).

  id, name, age, summary,

  parent: { 가정에서의모습, 강점재능, 우려요청, 또래형제관계, 양육방식 }, // 부모 5
  sensitivity: "상" | "중" | "하",  // 예민도

## 4. "오늘의 특징" 재검토 (결론: 별도 DB 없이 activity_records.memo 활용)

**원 기획 의도**: 아이가 평소와 다른 모습/특이사항을 보일 때 교사가 메모 → 관찰일지 AI에 반영해 정확도를 높임.

**재검토 결과**: "오늘의 특징"은 **원아별·날짜별로 교사가 런타임에 작성**하는 데이터입니다. 반면 `children-profiles.ts`는 **고정 시드(프로필 속성)**라, 날짜별 교사 메모를 담기에 부적합합니다. 따라서 **기질/부모 칼럼과 같은 시드 칼럼으로 넣지 않는 것**이 맞습니다.

**결정(2026-06-03):** "오늘의 특징"은 **별도 DB로 만들지 않고 `activity_records.memo`(원아별 한 줄 메모)를 그대로 활용**한다. 이미 `lib/teacher-context.ts` → `loadChildContext()`가 기간 내 `activity_records.memo`를 수집해 관찰일지 AI 프롬프트에 넣으므로, 교사가 특이사항을 한 줄 메모로 작성하면 **추가 구조 없이** 관찰일지 생성에 반영된다.

> 향후 관찰일지 AI 산출물은 **[활동 메모 + 특이사항 메모 + 원아 기질]을 종합**해 생성하는 것을 목표로 한다(아래 6장 검토 참조). 활동일지는 기질을 고려하지 않고 객관 사실만 유지한다.

## 5. TS 시드만 유지 시 이슈 (마이그레이션 미생성)

| 구분 | 이슈 |
|---|---|
| **편집 불가** | 프로필이 코드에 하드코딩 → 교사/원장이 화면에서 **수정·추가 불가**. 변경하려면 배포 필요 |
| **실데이터 불일치** | 시드 id(`siu` 등)는 Supabase `children` 테이블의 UUID와 **연결 안 됨** → 실제 원아와 매칭 불가 |
| **다중 사용자/동기화** | 파일은 빌드 시점 고정 → 여러 교사·실시간 반영 불가 |
| **"오늘의 특징" 저장 불가** | 런타임 입력을 시드에 저장 불가(4장 참조) → 별도 저장소 필요 |
| **개인정보** | 부모·기질 정보가 코드에 평문 → 저장소 RLS·접근제어 부재 |

**결론**: 프로토타입/데모·AI 프롬프트 입력용으론 TS 시드로 충분하나, **실제 운영(교사 편집·실원아 연동·오늘의 특징 저장)** 단계에선 Supabase 테이블(`child_temperament` 등) + RLS 마이그레이션이 필요합니다. 진행 시 010~012 패턴을 따르면 됩니다.

## 6. 검토: 메모·기질을 관찰일지 AI에 종합 반영 (활동일지와의 분리)

### 6-1. 특이사항 메모 → 관찰일지 AI (이미 배선 + 작은 갭 1개)
- `observations/new/actions.ts` → `loadChildContext()`가 기간 내 `activity_records.memo`를 수집해 프롬프트에 포함 → **특이사항을 한 줄 메모로 쓰면 자동 반영됨**.
- ⚠️ 갭: 활동기록 2단계의 "원아별 한 줄 메모"는 현재 sessionStorage 핸드오프로만 가고 **`activity_records.memo`에 저장되지 않음**(저장 액션은 활동 태그만 memo로 기록). 특이사항이 관찰일지에 반영되게 하려면 **한 줄 메모를 `activity_records.memo`에 저장하는 배선**이 필요.
- 한계: 일반 메모와 특이사항이 같은 `memo` 필드 → 구분/가중치 불가. 필요 시 접두어(예: `[특이]`)나 별도 플래그로 태깅.

### 6-2. 기질 → 관찰일지 AI (가능, 단 연결 필요)
- 메인 관찰일지 흐름은 현재 기질 미사용. 연결 방법:
  1. **원아 ↔ 기질 매핑** — 현재 시드 id(`siu`)와 실제 `children.UUID`가 분리 → 매핑 테이블/필드 필요 (TS-only의 핵심 블로커)
  2. `contextToPromptText()`에 해당 원아의 기질 5칼럼 주입
  3. 관찰일지 system prompt에 "기질을 고려해 해석" 지침 추가
- 결과: **[활동 메모 + 특이사항 + 기질]을 종합한 관찰일지** 산출 가능.

### 6-3. 활동일지는 기질 미고려 유지 (권장)
- 현재 활동기록(activities)은 기질 미사용 → **사용자 의도와 일치**.
- 기질을 활동일지에 넣을 경우:
  - **포지션 중복** — 기질 해석은 관찰일지의 역할. 활동일지에 넣으면 두 문서 역할이 겹침.
  - **객관성 저하** — 활동일지는 "무슨 활동을 했는가"의 사실 기록. 기질 해석이 섞이면 관찰일지가 해석할 원천 사실이 오염됨.
- 권장 분리: **활동일지 = 객관 사실** / **관찰일지 = 사실 + 기질 해석**. 둘을 잇는 다리는 **활동 메모(activity_records.memo)**.
- 결론: 활동일지에 기질을 넣는 것은 관찰일지에 도움이 되기보다 역할을 흐림. 기질은 관찰일지 생성 단계에서만 적용.

### 6-4. "기질 기반 기록 방식 + 옵션(이번주는 다르게)" 워크플로
- 기질 → 기록 지침 룩업: **가능**(정적 매핑 테이블).
- 부모 톤: 알림장에 톤 옵션 이미 존재(polish/shorten/warmer/formal) → 재사용 가능.
- ⚠️ 기간제 override + 자동 복귀(월~금만 성장중심 후 자동 원복): **런타임 상태 저장 필요** → TS-only로는 불가, **Supabase 테이블 필요**.
